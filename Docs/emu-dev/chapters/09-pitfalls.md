# Pitfalls checklist

One line per pitfall, with the lesson that explains it. Read the lesson before applying the line.

## Display

- A page or mode switch the game makes in the border must reach the copper list that is on screen, not only the next frame's list. Check it with a live-view freeze. ([A page switch shown a frame late (Barbarian's fighters vanish every second frame)](02-display-on-aga.md#a-page-switch-shown-a-frame-late-barbarians-fighters-vanish-every-second-frame))
- Put DDFSTRT on a fetch-unit boundary for the FMODE in use; a scroll that jumps by the fetch width is the symptom. ([The 32-bit fetch applies the scroll delay modulo 32, from the middle of a unit](02-display-on-aga.md#the-32-bit-fetch-applies-the-scroll-delay-modulo-32-from-the-middle-of-a-unit))
- Never derive a frame-wide register (the bitplane-enable word) from the last write of the emulated frame. Sample it where the display starts. ([One frame-wide register written by every R#1 write](02-display-on-aga.md#one-frame-wide-register-written-by-every-r1-write))
- Blank part of a frame by switching to a border-coloured palette bank, not by turning bitplane DMA off. ([Blanking a few lines in the middle of the picture](02-display-on-aga.md#blanking-a-few-lines-in-the-middle-of-the-picture))
- On a split line emit the bitplane pointers and BPLCON0 first and the colours after. ([Two bitmap modes in one frame (SCREEN 8 over SCREEN 5)](02-display-on-aga.md#two-bitmap-modes-in-one-frame-screen-8-over-screen-5))
- Two modes with different plane layouts need separate buffers, and the commands' results must be flushed to VRAM when a mode is left. ([Two bitmap modes in one frame (SCREEN 8 over SCREEN 5)](02-display-on-aga.md#two-bitmap-modes-in-one-frame-screen-8-over-screen-5))
- Map palette levels with a table to the nearest reference level, and check them against exact register values, not through a capture path that changes colours. ([3-bit levels to 4-bit nibbles: white was $EEE](02-display-on-aga.md#3-bit-levels-to-4-bit-nibbles-white-was-eee))
- Measure the real display window before sizing an edge mask or a crop. ([The window was exactly the picture, and the mask offsets hid 10 and 12 dots](02-display-on-aga.md#the-window-was-exactly-the-picture-and-the-mask-offsets-hid-10-and-12-dots))
- Restore BEAMCON0 (PAL/NTSC) and any other write-only display register on every exit path, from the system's own setting, then RemakeDisplay. A program that leaves NTSC timing behind breaks the next program's PAL screens. ([A 60 Hz game left the Amiga in NTSC timing after quitting](02-display-on-aga.md#a-60-hz-game-left-the-amiga-in-ntsc-timing-after-quitting))
- A PAL screen can sit on a 60 Hz beam that another program left behind (the screen is low and its bottom is cut). Measure the vertical blank time at start-up, log it, and put the PAL bit back when it is wrong. ([The other side: a PAL screen on a beam another program left at NTSC (Arnold)](02-display-on-aga.md#the-other-side-a-pal-screen-on-a-beam-another-program-left-at-ntsc-arnold))
- OS 3.2's `AllocScreenBuffer` refuses your own bitmap. Let Intuition allocate the buffers, aim their plane pointers into your memory, and put the originals back before `FreeScreenBuffer`. ([OS 3.2 refuses a screen buffer made from your own bitmap](02-display-on-aga.md#os-32-refuses-a-screen-buffer-made-from-your-own-bitmap))
- When the whole picture moves vertically, slide a display window over a taller buffer instead of rewriting the pixels, and prove it with the audit. ([When the picture moves up or down, move the window, not the pixels](02-display-on-aga.md#when-the-picture-moves-up-or-down-move-the-window-not-the-pixels))
- Ask for OSCAN_MAX to get 240 lines on NTSC and 272 on PAL; 362 pixels is all the beam shows horizontally on PAL, and WinUAE's window cuts 26 more columns on the left. ([A Plus picture is 384 pixels wide and the standard overscan shows 320](02-display-on-aga.md#a-plus-picture-is-384-pixels-wide-and-the-standard-overscan-shows-320))
- Design the menu for the shortest screen the program opens (200 lines on NTSC), with positions from the font height. ([A menu that fits 200 lines](02-display-on-aga.md#a-menu-that-fits-200-lines))
- If the host gives a palette entry a second meaning (Amiga colour 0 also fills the surround in the border colour), keep the emulated pens out of it, black included. ([Black pens must not share colour 0 when colour 0 is the border](02-display-on-aga.md#black-pens-must-not-share-colour-0-when-colour-0-is-the-border))
- A "too short to be a line" threshold in a monitor model squashes games that alternate the line length; compare with the reference emulator, and average the sync like a real monitor does. ([A line of 62 characters was refused, so two lines landed on one](02-display-on-aga.md#a-line-of-62-characters-was-refused-so-two-lines-landed-on-one))
- To follow a game's per-line backdrop on AGA, make a tile pixel of 0 truly index 0 (palette planes only where the row has a pixel). One copper MOVE to COLOR00 a line then reaches every such pixel, and BRDRBLNK keeps the sides from striping. ([A BG pixel of 0 made truly index 0: one copper MOVE a line follows the game's backdrop](02-display-on-aga.md#a-bg-pixel-of-0-made-truly-index-0-one-copper-move-a-line-follows-the-games-backdrop))
- BPLCON2 can put the sprites behind the playfield for a whole frame when all visible sprites agree. A mixed frame stays in front. ([Sprites behind the BG for a whole frame by BPLCON2, and why a mixed frame cannot use it](02-display-on-aga.md#sprites-behind-the-bg-for-a-whole-frame-by-bplcon2-and-why-a-mixed-frame-cannot-use-it))
- Mask a guest's index (tile, sprite, page number) to the guest's memory size before it indexes any host table. An index past the end reads memory nobody clears. ([A tile number past the end of the guest's memory read a flag nobody clears](02-display-on-aga.md#a-tile-number-past-the-end-of-the-guests-memory-read-a-flag-nobody-clears))
- In a renderer that caches by dirty flags, do not flag a write that leaves the value unchanged; games rewrite whole banks every frame. ([A write that changes nothing should not ask for a redraw](02-display-on-aga.md#a-write-that-changes-nothing-should-not-ask-for-a-redraw))

## CPU core

- No stack in handlers, or in anything they call: A7 may be a table pointer. Save registers in memory. ([A7 is a table pointer, not a stack](03-cpu-cores.md#a7-is-a-table-pointer-not-a-stack))
- If the core indexes with D1.L, keep the high word of D1 zero in every handler. ([D1's high word must stay zero](03-cpu-cores.md#d1s-high-word-must-stay-zero))
- Take a pending interrupt after the instruction that follows EI, not at the end of the line. ([A pending interrupt is taken after the instruction following EI, not at the end of the line](03-cpu-cores.md#a-pending-interrupt-is-taken-after-the-instruction-following-ei-not-at-the-end-of-the-line))
- A stack pointer can point into ROM: build it from the read pointer. A read-modify-write instruction needs both the read and the write pointer. ([The stack pointer in ROM: POP and RET read tables](03-cpu-cores.md#the-stack-pointer-in-rom-pop-and-ret-read-tables))
- Capture the flags immediately after the instruction that produces them: a 68k MOVE changes the CCR. Do not charge many cycles in one block. ([A MOVE changes the flags you are about to save](03-cpu-cores.md#a-move-changes-the-flags-you-are-about-to-save))
- Implement every parameter of a command (the logical operation of LINE), or a game that uses it will show the gap. ([A command that ignored the logical operation (VDP LINE)](03-cpu-cores.md#a-command-that-ignored-the-logical-operation-vdp-line))
- Never read host state (the beam) for an emulated register: it makes runs unrepeatable. ([Repeatable runs: `LD A,R` from emulated time](06-testing.md#repeatable-runs-ld-ar-from-emulated-time))
- Write branches to labels, never as `*+n`, and have the build refuse the pattern. ([Hand-counted branches break when the layout changes](07-toolchains-release.md#hand-counted-branches-break-when-the-layout-changes))
- A video-chip command that finishes instantly is a timing change: games pace mid-frame work on the busy flag. Keep drawing at once, but report busy for the real duration. ([A command that finishes instantly moves the game's mid-screen work up the frame](03-cpu-cores.md#a-command-that-finishes-instantly-moves-the-games-mid-screen-work-up-the-frame))
- Measure instruction costs; do not only read them. An empty macro argument cost DAA four cycles since 4.0. ([A generated test cartridge and a trace of the line counter find cost bugs that reading the code missed](03-cpu-cores.md#a-generated-test-cartridge-and-a-trace-of-the-line-counter-find-cost-bugs-that-reading-the-code-missed))
- Run the video chip to the instruction's own I/O cycle for `OUT` and `IN`, not to the end of the instruction; one early CRTC write can break a whole game (Pinball Dreams). ([Pinball Dreams: the CRTC saw each OUT at the start of its instruction](03-cpu-cores.md#pinball-dreams-the-crtc-saw-each-out-at-the-start-of-its-instruction))
- Memory-mapped chip registers (the Plus ASIC) need the same treatment as `OUT`, at the write's own NOP; and a cycle of lead past the end of an instruction must be carried to the next one, never made negative. ([A cycle of lead must be carried into the next instruction, never made negative](03-cpu-cores.md#a-cycle-of-lead-must-be-carried-into-the-next-instruction-never-made-negative))
- The Plus DMA runs just after the start of HSYNC, not at its end; code driven by DMA interrupts is late otherwise. ([The DMA ran at the end of HSYNC; the real ASIC runs it just after the start](03-cpu-cores.md#the-dma-ran-at-the-end-of-hsync-the-real-asic-runs-it-just-after-the-start))
- Tape pauses use the CPC's 4000 T-states a millisecond; fast tape may skip drawing and pacing but never the emulation. ([A tape pause was 12.5% too short, and loading took a minute and a half of real time](03-cpu-cores.md#a-tape-pause-was-125-too-short-and-loading-took-a-minute-and-a-half-of-real-time))
- Size the drive to the disk image: an 80-track image on a 43-track drive loses its later tracks. Write disks back with a temp file and rename the original away first (AmigaOS does not replace on rename). ([A disk image with 80 tracks, a drive with 43](03-cpu-cores.md#a-disk-image-with-80-tracks-a-drive-with-43))
- Fast-forward is pacing, drawing and sound only: switch it between frames, draw by real time (about 10 a second), keep making and filtering the sound but queue none, and restart the frame schedule on release, or the pacer bursts or skips to "catch up". ([Fast-forward: no pacing, a picture every 100 ms, sound paused, no catch-up](03-cpu-cores.md#fast-forward-no-pacing-a-picture-every-100-ms-sound-paused-no-catch-up))
- Start a tape (or any typed command) through the keyboard matrix at frame ends, from a frame measured on every model plus a margin, and keep its position in the save state; clear it fully when done. ([Tape auto-start: type the load command at frame ends, like a key script](03-cpu-cores.md#tape-auto-start-type-the-load-command-at-frame-ends-like-a-key-script))
- For a prefix like SET, run the next instruction from the prefix through a table of extra handlers, so that no hot handler tests a flag. ([The T flag: SET was a NOP, and it can be one step with the next instruction](03-cpu-cores.md#the-t-flag-set-was-a-nop-and-it-can-be-one-step-with-the-next-instruction))
- A rarely used mode (decimal) costs nothing if entering it repoints the dispatch table and every way out points it back. Remember the undefined flags of ABCD and SBCD. ([Decimal mode costs nothing while it is off: repoint the dispatch table](03-cpu-cores.md#decimal-mode-costs-nothing-while-it-is-off-repoint-the-dispatch-table))
- RTI must check for a pending interrupt, or a split falls one line late whenever another handler is running. ([RTI must take a pending interrupt, or a split lands one line late](03-cpu-cores.md#rti-must-take-a-pending-interrupt-or-a-split-lands-one-line-late))
- Raster and vblank on one line are two interrupts; a handler that tests one bit first starves the other if they are merged. ([Raster and vblank on one line are two interrupts](03-cpu-cores.md#raster-and-vblank-on-one-line-are-two-interrupts))
- The vblank interrupt line follows the game's display height, not a constant. ([The vblank interrupt follows the game's display height](03-cpu-cores.md#the-vblank-interrupt-follows-the-games-display-height))
- Your line start need not be the chip's: a scroll write just after it can still belong to the line before. ([A scroll write just after our line start still belongs to the line before](03-cpu-cores.md#a-scroll-write-just-after-our-line-start-still-belongs-to-the-line-before))
- Reads from video RAM may come from a read-ahead buffer filled earlier; find the exact rule with a test ROM. ([VRAM reads go through a read-ahead buffer](03-cpu-cores.md#vram-reads-go-through-a-read-ahead-buffer))
- Every read-modify-write instruction needs the same "is this I/O?" decision as LDA and STA. ([Read-modify-write instructions must reach the I/O handlers too](03-cpu-cores.md#read-modify-write-instructions-must-reach-the-io-handlers-too))
- A block move goes through the page register of every byte. Several faults in different titles can be this one. ([A block move goes through the page register of every byte](03-cpu-cores.md#a-block-move-goes-through-the-page-register-of-every-byte))
- An instruction that changes the clock speed is not a NOP: a boot delay loop that runs too fast can look like a graphics fault. ([CSL is not a NOP: a delay loop ran four times too fast](03-cpu-cores.md#csl-is-not-a-nop-a-delay-loop-ran-four-times-too-fast))
- Masking an address wraps it; the real chip may lose the write. Ask which before you mask. ([Writes past the end of VRAM are lost, not wrapped](03-cpu-cores.md#writes-past-the-end-of-vram-are-lost-not-wrapped))
- Run block instructions (`LDIR`, `OTIR` and the rest) a step at a time when a line ends mid-run, or a line interrupt waits for the whole copy. ([A long LDIR must let a line interrupt in between its steps](03-cpu-cores.md#a-long-ldir-must-let-a-line-interrupt-in-between-its-steps))

## Input

- Drive pin 6 high before pin 5 falls when reading a CD32 pad. ([Drive pin 6 high before pin 5 falls](05-input.md#drive-pin-6-high-before-pin-5-falls))
- Do not auto-detect a pad by identification bits; give each port an option, and reject the all-buttons-pressed pattern. ([Auto-detection by identification bits failed on real pads](05-input.md#auto-detection-by-identification-bits-failed-on-real-pads))
- Read the pad from code that uses no stack. ([A7 is a table pointer, not a stack](03-cpu-cores.md#a7-is-a-table-pointer-not-a-stack))
- Scripted test runs must ignore the host's keyboard, mouse and joysticks. ([Scripted runs must ignore the host's input](05-input.md#scripted-runs-must-ignore-the-hosts-input))
- Remap at the translation of keys, before anything else interprets them, behind one test; document that a remapped modifier stops acting as a modifier. ([Remap at the keyboard translation, behind one test](05-input.md#remap-at-the-keyboard-translation-behind-one-test))
- For every per-game setting, run one test that saves it, restarts and checks it was used (a case-sensitive keyword comparison hid a whole preferences path). ([Test the hook the way a user reaches it](05-input.md#test-the-hook-the-way-a-user-reaches-it))
- Log where each frame waits (VBlank and beam line at the end of the emulation, the input read and the render) before changing the frame loop for lag. ([Log where each frame waits before changing anything](05-input.md#log-where-each-frame-waits-before-changing-anything))
- Show a finished frame at once and wait afterwards; the tick wait paces the emulation, it should not hold a finished picture. This applies to a double buffer's commit too. ([Draw the frame as soon as it is emulated](05-input.md#draw-the-frame-as-soon-as-it-is-emulated), [Commit the double-buffered frame before the wait, too](05-input.md#commit-the-double-buffered-frame-before-the-wait-too))
- Before removing something that exists for the picture (a double buffer), get an A/B by eye on the player's display chain: good timing figures did not mean smooth scrolling. ([A faster path is not a better one until someone has looked at it](05-input.md#a-faster-path-is-not-a-better-one-until-someone-has-looked-at-it))
- Start each emulated frame at the guest's vblank line, so the game's pad read comes first and its result is drawn in the same frame. ([Start the emulated frame at the guest's vertical blank, not at its line 0](05-input.md#start-the-emulated-frame-at-the-guests-vertical-blank-not-at-its-line-0))
- On a machine with time to spare, start the frame late (the slowest recent frame plus a margin before the next vblank) and read the pad again first. ([On a fast machine, start the frame late and read the pad again first](05-input.md#on-a-fast-machine-start-the-frame-late-and-read-the-pad-again-first))
- Do not trust lowlevel.library's `ReadJoyPort()` for CD32 pads on a fast CPU (on a PiStorm it only ever reported red). Read the pad yourself, with every wait made of CIA reads. ([lowlevel.library only reported red on the PiStorm](05-input.md#lowlevellibrary-only-reported-red-on-the-pistorm); [kits/cd32pad](../kits/cd32pad/README.md))
- An emulator whose frame is a fixed cycle count from power on can lose a whole frame of lag to where that boundary falls in the game's frame. Measure the game's answer in whole frames, not only the host's time, and end the frame at the machine's VSYNC. ([End the frame at the machine's VSYNC](05-input.md#end-the-frame-at-the-machines-vsync))
- Give A/B builds neutral names (Preset A, Preset B) and ask one question; a name like "LateOff" steers the answer. ([Ask the tester the right question](05-input.md#ask-the-tester-the-right-question))

## Testing

- A snapshot taken after the render hides every race with the beam. Keep a live-view freeze for display faults. ([A SNAP freezes after the render, which is the one moment that is always consistent](06-testing.md#a-snap-freezes-after-the-render-which-is-the-one-moment-that-is-always-consistent))
- A key script that skips a screen never tests it. Write one that stays on the screen under test. ([A script that skips the screen under test](06-testing.md#a-script-that-skips-the-screen-under-test))
- Use exact-register captures (GDI output) for colour work; a boosted capture path hides real errors. ([WinUAE's default output boosts contrast and saturation](06-testing.md#winuaes-default-output-boosts-contrast-and-saturation))
- Make runs repeatable before trusting a pixel comparison, and mark captures that still vary. ([Repeatable runs: `LD A,R` from emulated time](06-testing.md#repeatable-runs-ld-ar-from-emulated-time))
- A stale baseline reports noise as change. Compare with the previous release's run. ([The tiers, baselines and the "varies" status](06-testing.md#the-tiers-baselines-and-the-varies-status))
- A cycle-exact 68030 in the emulator is not a fast CPU. Keep the real-hardware loop and put a build reference in every report. ([Use both loops, and keep a build reference that ties them together](06-testing.md#use-both-loops-and-keep-a-build-reference-that-ties-them-together))
- Do not let a product feature and the harness share a signal (the audio filter keeps the power LED lit). ([The power LED is the harness's signal](06-testing.md#the-power-led-is-the-harnesss-signal))
- Chain the run behind the lock's `mkdir` with `&&`, hold the lock at most 15 minutes, and run long tiers in chunks. ([A lock made with `mkdir`, and the one-character mistake that deleted another session's lock](08-agent-workflow.md#a-lock-made-with-mkdir-and-the-one-character-mistake-that-deleted-another-sessions-lock))
- Put debug code behind conditional assembly and check that the release build is byte-identical. ([Debug code must leave the release build byte-identical](07-toolchains-release.md#debug-code-must-leave-the-release-build-byte-identical))
- After a timing change, run a control build with the change switched off before calling any capture change a regression. ([A control build separates a timing change from a regression](06-testing.md#a-control-build-separates-a-timing-change-from-a-regression))
- Real-time grabs are scheduled in wall-clock seconds while key scripts count MSX frames; below full speed the two drift apart. ([Live window grabs run on the wall clock, the key script on MSX frames](06-testing.md#live-window-grabs-run-on-the-wall-clock-the-key-script-on-msx-frames))
- A V9938 line is 63.695 microseconds, not 64. ([Use the frame event and the vertical-retrace flag, not the interrupt probe](06-testing.md#use-the-frame-event-and-the-vertical-retrace-flag-not-the-interrupt-probe))

- A program started with `Run` does not get the remote shell's `Stack`; put `Stack` and the program in a script and `Execute` it. ([A program started with Run does not get the shell's stack](11-test-machine.md#a-program-started-with-run-does-not-get-the-shells-stack))
- Brackets in a path are wildcards for `Copy`/`List`: escape them with `'` in a source, reach a destination through an assign. ([Brackets are wildcards for Copy and List](11-test-machine.md#brackets-are-wildcards-for-copy-and-list))
- Remote screenshots do not show windowed MiniGL output, and SDL programs ignore injected mouse moves; test 3D full screen and drive SDL menus with keys. ([Driving the screen remotely](11-test-machine.md#driving-the-screen-remotely))
- Never Break a MiniGL program; one 3D context at a time (only if you run 3D programs on the test machine; see the appendix of chapter 11). ([One 3D context at a time, and never Break a 3D program](11-test-machine.md#one-3d-context-at-a-time-and-never-break-a-3d-program))
- Record the CM4 clock with every performance figure; a weak supply forces a lower clock. ([A marginal power supply looks like random resets under load](11-test-machine.md#a-marginal-power-supply-looks-like-random-resets-under-load))
- Give every behaviour change a `NO_x` switch that restores the old behaviour byte for byte; it turns a merge regression into a one-switch bisect. ([One switch per change, and what it buys](06-testing.md#one-switch-per-change-and-what-it-buys))
- Use an audit that reads the converted bitplanes back and checks the copper list, to tell an emulator bug from a display bug. ([AUDIT: telling an emulator bug from a display bug](06-testing.md#audit-telling-an-emulator-bug-from-a-display-bug))
- The x86 test host hides 32-bit bugs (`long` is 64 bits there) and cannot measure time; use WinUAE's exact-frame snapshots for pictures and the real machine for speed. ([A headless x86 host with per-frame checksums](06-testing.md#a-headless-x86-host-with-per-frame-checksums))
- Before a run on the real A1200 list its screens, record the use in the coordination file, make the run end by itself, and leave the machine at Workbench. ([Brief the run, and leave the machine as you found it](08-agent-workflow.md#brief-the-run-and-leave-the-machine-as-you-found-it))
- Check that every file a run script names exists before the first run; close a stranded program from its own menu, never with Break. ([Brief the run, and leave the machine as you found it](08-agent-workflow.md#brief-the-run-and-leave-the-machine-as-you-found-it))
- Windows shell traps for Amiga scripts: leading-slash paths are rewritten, and environment variables do not reach WSL without `WSLENV`. ([Windows shell traps for scripts that drive the Amiga](07-toolchains-release.md#windows-shell-traps-for-scripts-that-drive-the-amiga))
- Keep a patch series that equals the tree and check that each patch builds alone. ([Keep a patch series that equals the tree](07-toolchains-release.md#keep-a-patch-series-that-equals-the-tree))
- An `INCBIN` under a BSS section gives zeros and no error: a black boot, not a crash. ([INCBIN into a BSS section gives zeros, silently](07-toolchains-release.md#incbin-into-a-bss-section-gives-zeros-silently))
- For sweeps add the debug rows' windows up in a result file: totals, plus the tightest window. ([Add the windows up: run totals in a result file](06-testing.md#add-the-windows-up-run-totals-in-a-result-file))
- A debug panel moves the picture: look at a normal build before calling a row missing from a photo a fault. ([Add the windows up: run totals in a result file](06-testing.md#add-the-windows-up-run-totals-in-a-result-file))
- All switches on must rebuild the last binary, and each switch must also assemble alone; the all-at-once check cannot see the second. ([All switches on must rebuild the last binary, and each switch must assemble alone](06-testing.md#all-switches-on-must-rebuild-the-last-binary-and-each-switch-must-assemble-alone))
- A generated test ROM covers cases no game reaches. Sort its differences into classes before calling any of them a fault: undefined on the host, the reference's randomness, open bus, accepted limits, intended. ([Test ROMs compared byte for byte with the reference emulator](06-testing.md#test-roms-compared-byte-for-byte-with-the-reference-emulator))
- A fixed frame number compares moments: look at frames in a run and at the pair before believing a percentage. ([A frame number compares moments, not faults](06-testing.md#a-frame-number-compares-moments-not-faults))
- The reference emulator is not fully deterministic, and it carries state of its own such as a backup RAM file. ([A frame number compares moments, not faults](06-testing.md#a-frame-number-compares-moments-not-faults))
- Latch scripted input at the emulated frame, or builds of different speed diverge. ([Latch scripted input at the emulated frame, not at the host's vblank](06-testing.md#latch-scripted-input-at-the-emulated-frame-not-at-the-hosts-vblank))
- When every title gives "no result", suspect the rig first: a config can point at another checkout and give no error. ([A test config pointing at another checkout gives "no result" on every title](06-testing.md#a-test-config-pointing-at-another-checkout-gives-no-result-on-every-title))
- A memory guard takes the overrun that would crash the real build: read the guard report, and run long enough to reach the fault. ([A guard block catches the overrun, and so hides the crash](06-testing.md#a-guard-block-catches-the-overrun-and-so-hides-the-crash))
- When calls move within a loop, list the registers each needs on entry and who set them in the old order: a routine left A3 as its copper pointer, and the reload came after it. ([Reordering a frame loop moves calls before a register reload](06-testing.md#reordering-a-frame-loop-moves-calls-before-a-register-reload))
- Find a hang with variant builds that each change one thing (compiled out, padded to the same size, early returns at each stage), not by reading. ([Find a hang with variant builds, not by reading](06-testing.md#find-a-hang-with-variant-builds-not-by-reading))
- Write a test build's log with `PROGDIR:`, not the program's assign: a tester without the assign gets a "Please insert volume" requester. ([Write the log next to the program, not to its assign](06-testing.md#write-the-log-next-to-the-program-not-to-its-assign))
- Do not put `&` inside a command an agent already runs in the background: the subshell outlives the task, and a rerun then shares its slots and log. ([A subshell sent to the background keeps running after its task "finishes"](08-agent-workflow.md#a-subshell-sent-to-the-background-keeps-running-after-its-task-finishes))
- When the speed rows say "slow" but not why, count each redraw at the decision that causes it, then dump the guest's video memory to a file and read it on the PC. ([When the rows say "slow" but not why: probe counters, then a state dump](06-testing.md#when-the-rows-say-slow-but-not-why-probe-counters-then-a-state-dump))
- Look at one grab before trusting a comparison of grabs: two grabs of the wrong screen match perfectly. ([A grab of the wrong screen compares equal](06-testing.md#a-grab-of-the-wrong-screen-compares-equal))
- After any change to what a save state holds, run resume, round trip, "saving is invisible", refusals and fuzz checks, and load states across releases in both directions. ([Five checks, run headless on every change to the machine state](06-testing.md#five-checks-run-headless-on-every-change-to-the-machine-state))

## Sound and performance

- With the audio DMA off an enabled AUD0 interrupt storms (about 22,000 a second); switch the interrupt off with the DMA and on with it. ([With the audio DMA off, an enabled AUD0 interrupt does not stop](04-sound.md#with-the-audio-dma-off-an-enabled-aud0-interrupt-does-not-stop))
- Average a square wave over each output sample; point sampling aliases and sounds harsh. ([Square waves must be averaged over each output sample, not sampled at one point](04-sound.md#square-waves-must-be-averaged-over-each-output-sample-not-sampled-at-one-point))
- Bounds-check every lookup table; an index past the end read the next table by luck on the Amiga and gave crackle. ([A lookup table indexed past its end read another variable (crackle)](04-sound.md#a-lookup-table-indexed-past-its-end-read-another-variable-crackle))
- Compare sound as band levels against a reference render checked against another emulator, and confirm that the Paula data are identical to the test host's recording. ([Comparing WAV output with the reference emulator](04-sound.md#comparing-wav-output-with-the-reference-emulator))
- On Emu68, keep the usual path on the fall-through side of forward branches, keep hot loops under 128 bytes, avoid calls through registers (`-fno-function-cse`). ([On Emu68, the shape of the branches matters more than the instruction count](10-performance-emu68.md#on-emu68-the-shape-of-the-branches-matters-more-than-the-instruction-count))
- Code layout moves Emu68 timing by up to 0.9 ms a frame: compare builds only at fixed alignment, in turn, two runs each, and scan padding for the final layout. ([The same code runs faster or slower depending on where the linker puts it](10-performance-emu68.md#the-same-code-runs-faster-or-slower-depending-on-where-the-linker-puts-it))
- A profile-guided build is keyed by function order and line numbers; add new functions at the end of the file and re-record the profile (in WinUAE is fine) before a release. ([Profile-guided gcc builds recorded in WinUAE](10-performance-emu68.md#profile-guided-gcc-builds-recorded-in-winuae))
- Do not trust x86 instruction counts for the PiStorm; the CPU writes chip RAM faster than the blitter copies, so write only what changed. ([Chip RAM bandwidth and the CPU](01-target-hardware.md#chip-ram-bandwidth-and-the-cpu))
- Log the time of every frame, not only the average; the frames over the deadline are the finding. ([Measuring per frame on real hardware](10-performance-emu68.md#measuring-per-frame-on-real-hardware))
- With more channels than voices, pick the loudest each vblank with a bonus for the current owner, rather than mix per sample. ([Pick the four loudest channels each vblank instead of mixing](04-sound.md#pick-the-four-loudest-channels-each-vblank-instead-of-mixing))
- Set every Paula voice's period at start-up: a stale loop delayed the first buffer by 47 frames in WinUAE. Keep sample streams above tones, and do not stop a voice with buffers queued. ([Drums 100 ms late: a voice that was never given a period](04-sound.md#drums-100-ms-late-a-voice-that-was-never-given-a-period))
- Capture timer-driven samples on the timer's grid; a line grid adds a pattern tone. ([Samples written by a timer belong on the timer's grid, not the line grid](04-sound.md#samples-written-by-a-timer-belong-on-the-timers-grid-not-the-line-grid))
- Skip waiting loops by whole passes only while nothing but the CPU can change memory inside a line, and only outside pages that can hold I/O. ([Do not interpret a loop that can only wait](10-performance-emu68.md#do-not-interpret-a-loop-that-can-only-wait))
- Measure a speed-up on the machine it is for: +75% on a 68030 config changed nothing on the PiStorm's AGA path. ([The same work changed nothing on the PiStorm](10-performance-emu68.md#the-same-work-changed-nothing-on-the-pistorm))
- Switch a sound path (voice layout, software mix) only at power on or reset, never on Continue: live channel state is stranded on the old path. ([A sound path switched mid-game left a channel on the old path](04-sound.md#a-sound-path-switched-mid-game-left-a-channel-on-the-old-path))

## RTG output

- Do not call `ChangeScreenBuffer` from the emulation thread on the PiStorm's VideoCore: it waits for the 60 Hz flip inside the call (8-9 ms measured, against a 0.16 ms copy). Use one screen buffer and write the dirty lines under the lock; WinUAE's `uaegfx` hides the problem, so measure on the real board. ([Three screen buffers made every frame wait 8-9 ms](12-rtg.md#three-screen-buffers-made-every-frame-wait-8-9-ms))
- A flip task or a `ScrollVPort` page swap does not save the CPU on the VideoCore. The driver spins until the blank while it holds the board, so another task's lock waits too. For no tearing, find the blank with a pan pair and write the single buffer just after it (0.1-0.8 ms against a 16.7 ms scan). ([Every flip and every pan spins until the blank](12-rtg.md#every-flip-and-every-pan-spins-until-the-blank))
- Read the whole RTG mode list: the VideoCore lists about 580 modes, small ones first, and a 128-entry limit hid every mode above 400x300 (no 960x540, no 640-wide menu mode). Log how many modes were seen. ([Only the first 128 of 588 modes were looked at](12-rtg.md#only-the-first-128-of-588-modes-were-looked-at))
- For scanlines pick the mode the output scales by an exact integer (960x540 for 1080p HDMI); any other factor gives lines of uneven height. Check the scale against the real output, not the mode list. ([Pick the mode the board scales by exactly 2](12-rtg.md#pick-the-mode-the-board-scales-by-exactly-2))
- A frame skipped by a failed bitmap lock must keep its dirty lines owed inside the display code: a caller that clears its marks after every present would otherwise lose those lines for good. ([Three screen buffers made every frame wait 8-9 ms](12-rtg.md#three-screen-buffers-made-every-frame-wait-8-9-ms))
- On an 8-bit RTG screen with hard scanlines, entries 128-255 are the dimmed copies of 0-127: any pen the host draws over the picture (messages, labels) must be below 128 and reserved in the emulator's palette. ([An on-screen message drawn in pen 255 was black on an RTG screen with scanlines](12-rtg.md#an-on-screen-message-drawn-in-pen-255-was-black-on-an-rtg-screen-with-scanlines))
- Keep the menu, file requesters and error requesters on the RTG screen, and open the next screen before closing the old one, or the display leaves RTG at every Help. ([Open the next screen before closing the old one](12-rtg.md#open-the-next-screen-before-closing-the-old-one))
- A takeover emulator can use RTG too: read the framebuffer once, unlock before play, and make no OS or Picasso96 calls in play. Do not hold the lock across OS calls. ([A takeover emulator on RTG (AmiPCEngine)](12-rtg.md#a-takeover-emulator-on-rtg-amipcengine))
- A renderer that composes at frame end sees only the last value of each register: log every register a game changes between lines, with its line. ([The frame-end value of a register is not the frame](12-rtg.md#the-frame-end-value-of-a-register-is-not-the-frame))
- Measure the room left before tuning RTG: a PiStorm A1200 was busy 13 to 28% of all lines. ([Measure before tuning: RTG is busy 13 to 28% of the frame on a PiStorm](12-rtg.md#measure-before-tuning-rtg-is-busy-13-to-28-of-the-frame-on-a-pistorm))

- Pace on the clock the sound runs on. With Paula that is the chipset; with HDMI sound, time the frames to the HDMI blank: unlocked, the 0.14% beat lost 14 to 42 frames in 45 s. ([With HDMI sound, time the frames to the HDMI refresh](12-rtg.md#with-hdmi-sound-time-the-frames-to-the-hdmi-refresh))
- An anchor that pans to a second page and back can be held up for a whole refresh. Keep a copy of the picture on that page, so a late pan back repeats a frame instead of showing black. ([A missed pan back showed a black frame](12-rtg.md#a-missed-pan-back-showed-a-black-frame))
- Switch the A1200's LED filter off while your own sound plays, and put it back on every exit path; otherwise Paula's tone depends on the machine's state. ([Take the A1200's own filter out, then apply one tone to both outputs](04-sound.md#take-the-a1200s-own-filter-out-then-apply-one-tone-to-both-outputs))
